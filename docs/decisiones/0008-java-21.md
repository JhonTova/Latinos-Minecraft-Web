# ADR-0008 — Java 21 LTS para backend y plugin

- **Estado:** ✅ Vigente
- **Fecha:** 2026-08-03
- **Revisa:** la propuesta inicial del documento 08 (Java 25 backend / Java 21 plugin)

## Contexto

El documento 08 proponía Java 25 LTS en el backend y Java 21 en el plugin,
porque el plugin debe ejecutarse en servidores de clientes que corren la
versión de Java que exige su versión de Minecraft.

Al inspeccionar el entorno de desarrollo se confirmó: **Java 21.0.9 LTS
instalado**, Maven 3.9.12, sin Gradle.

## Decisión

**Java 21 LTS en todo el proyecto**: backend, plugin y módulos compartidos.

## Justificación

| Criterio | Efecto |
|---|---|
| Compatibilidad con el plugin | El plugin debe ser Java 21 de todos modos. Una sola versión elimina la gestión de dos targets. |
| Módulos compartidos | Los DTOs y contratos compartidos entre backend y plugin ya no necesitan compilarse al mínimo común: **son el mismo target**. |
| Soporte | Java 21 es LTS con soporte de larga duración. Sin riesgo de quedarse atrás en años. |
| Virtual Threads | Disponibles y estables en 21. Es la característica que más importa aquí (heartbeats masivos de E/S). |
| Entorno | Ya instalado. Cero fricción de arranque. |

La ventaja real de Java 25 sobre 21 para este proyecto es marginal, y no
compensa mantener dos versiones y una matriz de compatibilidad.

## Consecuencias

- Desaparece el riesgo señalado en el documento 08 (plugin que no arranca por
  target de bytecode superior al del servidor del cliente)
- El módulo `shared` se compila una sola vez para ambos consumidores
- Revisar en 2028 si conviene migrar a un LTS posterior; será un cambio
  coordinado de backend y plugin, no independiente
